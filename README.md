# Agent Design Toolkit

From user experience design to agentic system design — a live tool that translates a user story into a structured agent spec across seven dimensions.

> **This is a fork.** The toolkit was created by [Prasad MK](https://github.com/prasadmks); the original is at [prasadmks/agent-design-toolkit](https://github.com/prasadmks/agent-design-toolkit). This fork, maintained by [Jay Ungerland](https://github.com/jungerland), keeps it running on current Claude models and adds fixes. See [What's changed in this fork](#whats-changed-in-this-fork).

**Run it:** open `index.html` in a browser, or use the [local proxy](#optional-run-with-a-local-proxy). An Anthropic API key is required to generate specs. To view past outputs, browse the [sample output](#sample-output) below.

**Hosted version:** Prasad's original is hosted at [v0-agent-design-toolkit.vercel.app](https://v0-agent-design-toolkit.vercel.app). It is a separate app whose code is not in this repo, so it does not include the changes in this fork.

## What's Changed in This Fork

- **Current model.** The original called `claude-sonnet-4-20250514`, which Anthropic has retired, so every request failed. All three calls now use `claude-sonnet-5-5`.
- **Fallback if the model is retired again.** If the pinned model is not found, the page looks up the newest Sonnet model, retries with it, and shows a notice saying which model generated the spec.
- **Response parsing.** Newer models can return a thinking block before the text. The page now reads the text blocks instead of assuming the first block is text, raises the output limits to fit measured Sonnet 5.5 usage, and shows a clear error if a response is cut off.
- **Optional local proxy** (`server.js`), so your API key stays in a `.env` file on your machine instead of being pasted into the page.

## The Problem

A user story defines what the system should do. It says nothing about how the agent underneath should reason, determine what needs to be loaded in memory, what happens when a tool call fails, or how its decisions get evaluated. That gap lives between product and engineering — and it's where most agentic projects lose definition.

Most teams discover what they forgot to specify after the first production incident. This toolkit makes that layer explicit before build starts.

## How It Works

[![Agent Design Toolkit Architecture](https://raw.githubusercontent.com/prasadmks/agent-design-toolkit/main/images/architecture.png)](https://raw.githubusercontent.com/prasadmks/agent-design-toolkit/main/images/architecture.png)

Paste a user story. The toolkit generates a complete agent design spec across seven dimensions — each one a decision that typically gets resolved informally during sprint planning, or not at all.

| # | Dimension | Who owns it |
|---|---|---|
| 1 | Requirement Interpretation | PM + Engineering · confirm together |
| 2 | Open Decisions | PM · answers before build starts |
| 3 | Knowledge Base Design | PM specifies · Data eng implements |
| 4 | Memory Design | PM decides · Engineer implements |
| 5 | Tool Contracts | PM specifies · Engineer implements |
| 6 | Logging Schema | PM defines · Engineer builds |
| 7 | Eval Design | PM writes cases · QA implements |

---

## The Design Decision

Writing requirements for deterministic software is a solved problem. Writing requirements for an agent — something that reasons, fails unpredictably, and makes autonomous decisions — is not.

| Characteristic | User Story | Agent Design Spec |
|---|---|---|
| Captures expected behavior | Yes | Yes |
| Defines memory architecture | No | Yes |
| Specifies tool contracts | No | Yes |
| Sets confidence thresholds | No | Yes |
| Defines fallback paths | No | Yes |
| Includes eval cases | No | Yes |

### Optional: run with a local proxy

To avoid pasting your API key into the page, run the included proxy. It serves the tool and adds your key from the environment, so the key never reaches the browser. Requires Node 20.6+.

Put your key in a `.env` file in the repo folder (it's gitignored):

```
ANTHROPIC_API_KEY=sk-ant-...
```

Then start the proxy:

```
node --env-file=.env server.js
```

Avoid exporting `ANTHROPIC_API_KEY` in your shell profile (`~/.zshrc`, `~/.bashrc`). Other tools read that variable too. Claude Code, for example, will bill that API key instead of your Claude subscription.

Then open http://localhost:8787. When loaded from localhost, the page uses the proxy automatically; opened any other way, it works as before.
